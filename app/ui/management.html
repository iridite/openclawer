Base URL 与 API Key 说明

Base URL 是 API 根地址，API Key 是访问凭据。两者任意一项错误都会导致请求失败。

填写原则：

  • Base URL 以供应商文档为准：有的要求域名根路径，有的要求带 /v1 或前缀路径。
  • OpenClaw 会根据“API 协议/类型”拼接请求路径；请确保 Base URL 与协议/类型匹配。
  • API Key 请去除首尾空格与换行；建议使用 https://，并确认模型/权限/地域已开通。

快速排查：

  • 404：优先检查 Base URL 是否应包含 /v1 或特定前缀路径。
  • 401/403：API Key 无效、权限不足、模型未开通。
  • 400 no body：常见于模型 ID、Base URL、API 协议/类型不匹配。
  • 429：配额不足或触发限流；5xx/超时：上游服务或网络链路异常。

示例（OpenAI 兼容）： 

Base URL: https://api.openai.com/v1
API 类型: openai-completions
实际请求: https://api.openai.com/v1/chat/completions

如遇 404，请回到供应商文档核对 Base URL：
- 有的服务要求 https://api.openai.com/v1
- 有的服务要求 https://api.openai.com

渠道配置引导

本区集中说明各渠道的关键字段与最小示例，减少频繁跳转文档的成本。若需要更复杂的能力，请在下方配置编辑器中补充完整配置。

Telegram

关键字段：botToken 为必填；推荐 dmPolicy 使用 open，allowFrom 使用 ["*"]；群组模式用 groups["*"].requireMention 控制是否需要 @ 提及。 

{
  "telegram": {
    "enabled": true,
    "botToken": "123:abc",
    "dmPolicy": "open",
    "allowFrom": ["*"],
    "groups": { "*": { "requireMention": true } }
  }
}

Discord

关键字段：token 为必填；最小配置即可上线，建议先验证连接再配置其他权限。 

{
  "discord": {
    "enabled": true,
    "token": "bot_token"
  }
}

飞书

关键字段：accounts.main.appId 与 appSecret 必填；建议 dmPolicy 先用 open 以降低接入成本。 

{
  "feishu": {
    "enabled": true,
    "dmPolicy": "open",
    "accounts": {
      "main": {
        "appId": "cli_xxx",
        "appSecret": "xxx",
        "botName": "MyBot"
      }
    }
  }
}

QQ

关键字段：appId 与 clientSecret 必填；allowFrom 建议为 ["*"]。QQ 需要安装插件，未安装时保存会提示并引导安装。 

{
  "qqbot": {
    "enabled": true,
    "allowFrom": ["*"],
    "appId": "1903xxxx",
    "clientSecret": "xxxx"
  }
}

企业微信

关键字段：botId、 secret 与 dmPolicy；建议 dmPolicy 先使用 open。企业微信 需要安装插件，未安装时保存会提示并引导安装。 

{
  "wecom": {
    "enabled": true,
    "botId": "ww_xxx",
    "secret": "xxx",
    "allowFrom": ["*"],
    "dmPolicy": "open"
  }
}
其他未在表单内置的渠道类型，可在配置编辑器中按官方文档补充字段与结构。

配置编辑器

导入 / 导出使用指南

按钮用途

  • 导出配置：仅导出当前 openclaw.json。
  • 导入配置：导入 openclaw.json（支持粘贴或上传 JSON），并尝试自动重启 Gateway。
  • 导出完整备份：导出配置 + 记忆 + 插件目录，生成 .tar.gz。
  • 导入完整备份：恢复配置 + 记忆 + 插件目录，系统会先自动创建导入前备份。

推荐流程

  1. 日常改配置前，先点一次“导出配置”做轻量备份。
  2. 跨设备迁移、重大升级前，使用“导出完整备份”。
  3. 迁移后优先用“导入完整备份”；仅改配置时再用“导入配置”。
  4. 导入完成后检查：主模型、消息渠道、插件状态是否符合预期。

最佳实践

  • 备份文件建议保留至少两份，并存放到 NAS 外部位置（本机 + 异地/云端）。
  • 完整导入会触发重启，建议在低峰时段执行，避免中断会话。
  • 仅导入可信来源的备份；JSON 导入失败时请先修复语法错误。
  • 如导入后行为异常，请先回滚到系统自动生成的导入前备份。

提示：配置校验出现警告时，系统会提示风险但通常不阻断保存；请结合实际场景判断是否继续。

导入 openclaw.json

支持直接粘贴 JSON，或上传 `.json` 文件。 仅在 JSON 语法合法时才会应用，并自动重启 Gateway。

如需恢复记忆与插件，请使用上方“导入完整备份”按钮上传 `.tar.gz` 备份包。

更新说明

OpenClaw 核心更新

OpenClaw 核心通过 npm 安装，支持在线更新。

  1. 点击上方「检查更新」，确认是否有新版本。
  2. 有新版本时，点击「更新版本」。
  3. 系统自动执行：npm install openclaw@latest。
  4. 更新完成后，重启 Gateway 使新版本生效。

FPK 应用更新

如需更新整个 OC-Deploy（管理界面、脚本、服务逻辑），请通过飞牛应用中心更新 FPK。

  1. 打开飞牛应用中心。
  2. 检查 oc-deploy 是否有新版本。
  3. 下载并安装最新 FPK。
  4. 应用会自动重启并应用新版本。

注意事项

  • 更新前建议先导出备份（系统也会自动备份）。
  • 更新期间 Gateway 会短暂中断服务。
  • 更新完成后建议检查配置与运行状态是否正常。
  • 故障排查日志：/var/apps/oc-deploy/var/openclaw.log
